你正在开发 FormaSpace 图片转3D项目。

本轮目标：
将已经验证成功的真实中间点云逻辑接入 Python 常驻推理服务，
供 Spring Boot 通过 HTTP 提交任务、通过 WebSocket 订阅事件。

这份提示词同时提供给 Python 和 Java 开发者，双方必须遵守以下协议。
负责 Python 仓库时，只实现 Python 部分；
负责 Java 仓库时，只实现 Java 对接部分。
先阅读现有项目，复用现有普通生成链路，不凭空假设已有接口。
如果现有接口与本协议不同，增加适配并明确说明，不静默改变协议。

一、现状和范围

Python 项目：formaspace-inference。
已完成 scripts/preview_probe.py：

- Hunyuan3D-2mini，MPS，无纹理。
- 30步采样，第24步提取真实中间latent。
- 解码为128分辨率网格，表面采样5000个点。
- 最终256分辨率GLB继续正常生成。
- 同步预览约暂停采样6秒。
- 单图同seed对照的最终GLB完全一致。

先阅读上述脚本和相关文档，以实际代码为准。
提取可复用模块，让验证脚本和任务服务共享推理实现；
不要在HTTP请求中执行验证脚本或为每个请求启动Python子进程。
不改前端，不实现纹理，不升级已固定依赖，不删除模型缓存。

二、连接方向和地址

Python是HTTP/WebSocket服务端，Java是客户端。

默认开发地址：
HTTP：http://127.0.0.1:8001
WS：ws://127.0.0.1:8001

Java通过HTTP提交任务，再连接该任务的WebSocket。
任务执行不得依赖WebSocket是否连接。
所有URL路径均为本轮约定，需要实际实现，不能假设Gradio已有。

Python与Java部署到不同机器后：
由配置替换host和port，不能依赖共享文件系统。
Python现有Gradio入口仍可保留，但不要与新服务同时占用GPU。
新服务使用单个进程、单个推理worker。

三、鉴权

服务间共享令牌，从环境变量 INFERENCE_API_TOKEN 读取。
HTTP和WebSocket握手统一使用：

Authorization: Bearer <token>

Java从配置读取令牌，不硬编码、不写入日志。
除health检查外，任务、快照、下载、WebSocket接口均验证令牌。
服务启动时未配置令牌应明确失败。
开发默认绑定127.0.0.1，部署时自行配置监听地址。
本轮使用原生WebSocket JSON协议，不使用STOMP或SockJS。

四、HTTP接口

1. GET /healthz

存活检查，返回200。
不加载新模型，不触发推理。

2. GET /readyz

模型已成功加载、服务可接收任务时返回200；
初始化中或worker不可用时返回503。
可返回ready、modelId、device、queueDepth。

3. POST /api/v1/tasks

multipart/form-data：

- taskId：Java生成的UUID字符串，必填。
- image：图片文件，必填。
- parameters：JSON字符串，可选。

默认parameters：
{
"seed": 1234,
"steps": 30,
"guidanceScale": 5.0,
"finalResolution": 256,
"previewEnabled": true,
"previewStep": 24,
"previewResolution": 128,
"pointCount": 5000,
"numChunks": 4000
}

校验：

- previewEnabled=true时，1 <= previewStep < steps。
- 参数设置合理上下限，限制图片尺寸和上传大小。
- 首版限制预览一次、最多5000点，避免客户端任意放大计算量。
- 校验图片实际可解码，不能只检查扩展名。
- 图片校验与接收不能阻塞事件循环。

提交成功返回202：
{
"taskId": "<UUID>",
"status": "queued",
"snapshotPath": "/api/v1/tasks/<UUID>",
"eventsPath": "/api/v1/tasks/<UUID>/events"
}

这些Path都是相对Python服务地址的路径。

任务按taskId幂等：

- 相同taskId、相同图片内容和规范化参数：返回已有任务，
  不重复入队、不重复推理。
- 相同taskId但请求内容不同：返回409。
- 对并发重复提交进行原子保护。
- HTTP提交超时后Java可使用同一taskId重试。

队列必须有容量上限；满时返回429。
提交返回后不等待生成完成。
HTTP客户端断开不取消已接收任务。

4. GET /api/v1/tasks/{taskId}

返回任务快照，例如：
{
"taskId": "<UUID>",
"status": "running",
"sequence": 27,
"stage": "sampling",
"completedSteps": 24,
"totalSteps": 30,
"previewVersion": 1,
"latestPreview": {
"version": 1,
"sourceStep": 24,
"pointCount": 5000,
"positionsPath": "/api/v1/tasks/<UUID>/previews/1"
},
"result": null,
"error": null
}

没有预览时latestPreview=null。
成功时result：
{
"modelPath": "/api/v1/tasks/<UUID>/result",
"format": "glb"
}

失败时error：
{
"code": "INFERENCE_FAILED",
"message": "可对外展示的简短信息"
}

不存在返回404。
不要通过接口返回本机绝对路径或完整traceback。

5. GET /api/v1/tasks/{taskId}/previews/{version}

返回该版本完整点云JSON：
{
"taskId": "<UUID>",
"previewVersion": 1,
"sourceStep": 24,
"pointCount": 5000,
"positions": [[0.1, 0.2, 0.3]]
}

坐标必须有限，点数必须与positions长度一致。
不做逐预览独立归一化，保留与最终模型一致的坐标系。
文件未就绪返回404。

6. GET /api/v1/tasks/{taskId}/result

任务成功后返回GLB文件，Content-Type=model/gltf-binary。
任务存在但结果未就绪返回409；任务不存在返回404。
从受控任务目录读取，不接受任意本地文件路径。

五、WebSocket协议

地址：
/api/v1/tasks/{taskId}/events

Java主动连接，Python主动推送，不通过该连接启动推理。
连接成功后第一条消息必须是task_snapshot。
不存在的任务和鉴权失败在握手阶段拒绝，
或按框架能力使用明确且文档化的关闭码。

统一事件结构：
{
"protocolVersion": 1,
"taskId": "<UUID>",
"sequence": 27,
"type": "preview_ready",
"stage": "sampling",
"completedSteps": 24,
"totalSteps": 30,
"previewVersion": 1,
"timestamp": "<UTC ISO-8601>",
"payload": {}
}

字段语义：

- sequence：单任务持久事件序号，严格递增。
- completedSteps：真实已完成采样步数，从0到totalSteps。
- 采样完成不等于任务完成；30/30之后仍可能解码和导出。
- previewVersion：从0开始，仅成功保存新预览后加1。
- timestamp：服务端UTC时间。
- 所有消息是完整JSON文本，不发送NaN或Infinity。
- 预览消息是完整点云快照，不是增量。

事件类型和stage：

task_queued / queued
task_started / preprocessing
sampling_step / sampling
preview_started / preview_decoding
preview_ready / sampling
preview_failed / sampling
finalizing / final_decoding
task_completed / completed
task_failed / failed

task_snapshot：

- 是连接时的控制消息，不额外增加sequence。
- sequence等于快照对应的最后持久事件序号。
- payload为HTTP快照的完整内容。
- terminal任务也可连接，先收到最终快照。

preview_ready的payload：
{
"sourceStep": 24,
"pointCount": 5000,
"positions": [[0.1, 0.2, 0.3]],
"positionsPath": "/api/v1/tasks/<UUID>/previews/1",
"decodeSeconds": 6.2
}

首版5000点直接通过WS发送完整坐标。
HTTP positionsPath用于重连恢复，不发送本机文件路径。
首次成功预览对应previewVersion=1。

preview_failed的payload：
{
"code": "PREVIEW_DECODE_FAILED",
"message": "本次中间预览生成失败",
"fatal": false
}

普通预览失败不使任务失败，也不增加previewVersion。
不可恢复的设备错误先记录失败原因，再进入task_failed。

task_completed的payload：
{
"modelPath": "/api/v1/tasks/<UUID>/result",
"format": "glb"
}

task_failed的payload：
{
"code": "INFERENCE_FAILED",
"message": "简短错误说明"
}

六、任务与线程模型

启动时加载模型一次，复用实例。
单worker串行执行GPU推理，队列有容量上限。
推理运行在专用工作线程，不能阻塞FastAPI事件循环。
采样和同步预览始终在同一个推理线程；
禁止多个线程同时使用同一模型。
不在推理回调中等待网络发送。

工作线程产生事件后：

1. 更新任务快照并记录本地events.jsonl。
2. 以线程安全方式通知异步发送层。
3. 异步发送层向订阅者推送。

订阅者缓冲队列有上限。
慢连接不能拖住GPU线程或导致无限内存增长；
队列溢出时断开该订阅连接，让其通过快照恢复，
不能悄悄丢掉终态并伪装为完整事件流。

点云文件先写临时文件再原子替换，
保存成功后更新previewVersion并发布preview_ready。
结果文件完成保存后再发布task_completed。
事件写入和快照更新要保证一致顺序。

保留真实latent预览路径和独立RNG。
不能使用最终模型伪造中间点云。

七、重连与进程重启

WebSocket断开只注销订阅，不取消任务。
Java使用指数退避重连，最大间隔有上限。

每次新连接：

- Python先原子获取快照并注册后续事件订阅，
  避免“快照生成到订阅建立之间”遗漏事件。
- 先发送task_snapshot，再发送sequence更大的事件。
- 首版不要求完整历史重放，快照用于恢复当前状态。
- Java发现sequence跳跃时重新连接获取快照。
- Java忽略已处理的重复旧事件。
- 快照恢复时若有新previewVersion，通过HTTP拉取点云。
- 重连不能重新提交或重新执行同一个任务。

本地持久化任务元数据、事件、预览和最终文件。
首版不恢复中断的GPU计算：
服务重启后，原queued/running任务标记为failed，
错误码SERVICE_RESTARTED，并保留已有预览。
已完成任务仍可查询和下载。
不得将遗留任务永远显示为running。

八、Python交付要求

- 独立的常驻API启动入口，模块结构清晰。
- 共享推理与预览模块，保留preview_probe验证入口。
- 服务单进程运行，不开启reload，不启动多个worker。
- 使用现有FastAPI/Uvicorn依赖，必要新增依赖明确说明。
- 输出Mac单行启动命令，包含MPS fallback环境变量。
- 输出curl提交、查询、下载的示例。
- 提供HTTP/WS协议文档、配置项、错误码和Java接入说明。
- 文档明确：Path相对于Python服务，不是Java地址。

九、Java对接要求

先阅读现有生成任务服务，复用数据库任务和权限体系。

- Java生成taskId并先建立本地任务记录。
- multipart HTTP提交图片与parameters。
- 提交成功后作为原生WebSocket客户端连接Python。
- HTTP及握手均携带服务令牌。
- 配置Python baseUrl、token、超时、重连参数。
- 任务提交与WS订阅均不得长期占用Servlet请求线程。
- 按taskId管理连接，完成或失败后释放资源。
- 正确解析task_snapshot和增量事件。
- 使用sequence去重，previewVersion避免重复加载点云。
- 收到点云后更新任务预览状态，预留向前端转发入口。
- 不将Python内部地址和令牌直接暴露给浏览器。
- 最终GLB由Java下载并存入现有文件存储，
  不将Python机器的路径当作本地路径。
- WS断开显示“连接恢复中”，不能直接把生成任务判失败。
- 重连快照为completed时补下载结果，为failed时同步失败。
- 服务重启或超时后的任务使用同一taskId查询和协调，
  不自动创建重复推理任务。
- 本轮前端转发可预留，不要求改前端。

十、验收

优先用已验证成功的图片、seed及模型参数。

必须验证：

1. HTTP提交立即返回，任务异步执行。
2. Java收到快照、真实采样进度、第24步点云和完成事件。
3. WS预览包含5000个有效坐标，最终GLB能跨HTTP下载。
4. 采样30/30后仍正确显示final_decoding，直至真正完成。
5. 第20步主动断开WS，推理继续；重连后恢复状态。
6. 预览之后重连，可通过快照和HTTP恢复最新点云。
7. 生成完成后再订阅，也能获知终态和结果地址。
8. 相同taskId重复提交不会重复推理，不同内容返回409。
9. 两个任务串行推理，HTTP和WS仍可及时响应。
10. 普通预览失败，最终生成继续。
11. 慢订阅者不阻塞推理。
12. Python重启后，中断任务不会残留running状态。

可以用轻量假推理器测试协议和断线逻辑，
但必须与真实模型测试明确区分。
没运行Java就不能宣称Java联调成功；
仅用Python客户端验证时需如实标注。
