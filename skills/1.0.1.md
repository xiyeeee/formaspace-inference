本阶段只改 Python 项目，不改 Java、前端，不接 WebSocket。

先阅读本地代码，以本地版本的函数签名为准：

- hy3dgen/shapegen/pipelines.py
- 相关 scheduler 实现
- gradio_app.py 中的图片预处理与推理调用

目标：
一次图片转 3D 推理，在第 24/30 步导出真实中间点云，
然后继续完成剩余采样并导出 final.glb。

实现要求：

1. 新增独立入口 scripts/preview_probe.py。
   不改变现有 Gradio 默认行为。
   支持 image、output-dir、seed、steps、preview-step 参数。
   默认使用：
   tencent/Hunyuan3D-2mini
   hunyuan3d-dit-v2-mini
   device=mps，关闭纹理
   steps=30，preview-step=24
   最终分辨率256，预览分辨率128，num_chunks=4000。

2. 复用现有图片预处理，保证与 Gradio 输入路径一致。
   在推理调用中传 callback 和 callback_steps=1。
   检查回调索引语义，对外 completedSteps 从1开始计数。

3. 每次回调记录真实步数。
   只在选定步骤取得 outputs.prev_sample.detach().clone()。
   不把 latent 张量直接当作 XYZ。
   不修改原始 latent、scheduler、模型参数或全局随机数状态。

4. 在同一推理线程同步执行一次预览解码。
   复用 pipeline.\_export 的完整解码流程，以关键字参数调用，
   包括正确的 VAE scale_factor 处理。
   使用 mc 算法，预览分辨率128。
   不要重复加载模型，不要另开线程并发使用同一 GPU 模型。
   必须说明：同步预览会短暂暂停后续采样，增加总耗时。

5. 检查解码结果：
   容器非空、mesh非None、顶点和三角面非空、坐标有限。
   网格有效时，从表面按面积采样约5000个点，
   使用独立随机数生成器，避免影响后续推理。
   保存 preview_step_024.ply 和 preview_step_024.json。
   JSON包含 positions: [[x,y,z], ...]。
   保留原始模型坐标系，不对每次预览单独居中缩放。

6. 预览解码或采样失败时：
   保存完整异常日志并记录 preview_failed 事件，
   不伪造点云，不用最终模型冒充中间结果。
   普通预览异常应允许最终生成继续。
   GPU内存或设备错误若无法安全恢复，要明确报告失败。

7. 推理结束后正常导出 final.glb。

8. 事件先写本地 events.jsonl，统一包含：
   taskId、sequence、type、stage、
   completedSteps、totalSteps、previewVersion。
   sequence在单个任务中严格递增；
   previewVersion只在成功保存预览后增加。
   预览成功事件可额外包含文件路径、pointCount和解码耗时。
   当前不实现断线恢复，保留后续扩展空间。

9. 输出 summary.json：
   模型配置、seed、预览实际步骤、点数、
   预览耗时、总耗时、最终生成状态。
